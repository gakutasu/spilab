# SPI学習Webアプリ 仕様書（ユーザー提供・原文）

## 1. プロジェクト概要

転職活動向けSPI対策を目的とした、個人学習用Webアプリを開発する。

単純な正誤だけではなく、

* 正解したか
* 間違えたか
* 「わからない」を選んだか
* 解答まで何秒かかったか
* どの分野の問題か
* 同じ分野で過去にどの程度正解しているか

を継続的に記録し、ユーザーごとの得意・不得意を推定する。

その結果を次回以降の出題割合に反映し、苦手分野を重点的に練習できることを最大の特徴とする。

公開して他ユーザーも利用できるWebアプリとする。

## 2. 開発方針

技術構成: React / TypeScript / Vite / GitHub / GitHub Pages。CSSはTailwind CSSでも通常CSSでも可。バックエンドなし、AI APIなし、外部有料サービスなし。無料で継続利用できることを最優先する。

データ保存: 初期版ではブラウザ内に保存する。推奨は IndexedDB。ログイン機能は初期版では不要。ユーザーの学習履歴はブラウザローカルにのみ保存する。

## 3. 公開

GitHub Pagesで公開する。GitHub Actionsを利用し、mainブランチへのpush → build → GitHub Pagesへdeploy を自動化する。

READMEには以下を記載する: アプリ概要 / URL / 開発環境 / 起動方法 / build方法 / 問題追加方法 / ライセンス

## 4. 基本学習フロー

1問ずつ学習する。

STEP 1: 問題文と選択肢を表示する。この段階ではタイマーを開始しない。「問題をはじめる」ボタンを表示する。

STEP 2: 「問題をはじめる」を押した瞬間にタイマー開始。問題文と回答UIを操作可能にする。表示する回答: A / B / C / D / わからない。「わからない」は通常の選択肢とは明確に区別する。

## 5. 解答時間

「問題をはじめる」を押した瞬間に startTime を記録。回答選択後「解答する」を押した瞬間に answeredTime を記録。answerTime = answeredTime - startTime。単位はミリ秒で保存し、UI上では秒表示する（例: 解答時間：32.4秒）。

## 6. 個別採点

一括採点にはしない。1問ごとに、問題開始 → 回答 → 解答する → 採点 → 解説 → 次の問題。「解答する」を押すまでは正解を表示しない。

## 7. わからない

必ず独立した「わからない」ボタンを設ける。当てずっぽうによる正解を学習データに混ぜないためである。「わからない」を選んだ場合 result = unknown とし、通常の不正解とは別のデータとして記録する。

## 8. 採点後画面

「解答する」を押した後に以下を表示する: 正誤（正解 / 不正解 / 解法未習得）、自分の回答、正解、解答時間、目安時間（recommendedTime）との比較（例: 42秒 / 目安30秒）。

## 9. 詳細解説

採点後に必ず詳細な解説を表示する。単純に「Cが正解です」では不十分。特に計算問題では以下を説明する。

1. この問題が何の問題なのか
2. どう考え始めればいいか
3. なぜその式になるか
4. 式
5. 途中計算
6. 正解
7. 間違えやすいポイント

## 10. 問題データ

問題はコードに直接埋め込まず、JSONまたはTypeScriptデータファイルとして管理する。

```ts
{
  id: "nonverbal-permutation-001",
  category: "nonverbal",
  topic: "permutation",
  subtopic: "role_assignment",
  difficulty: 2,
  question: "7人の候補者から部長1人と副部長1人を選ぶ方法は何通りありますか？",
  choices: ["21通り", "35通り", "42通り", "49通り"],
  correctChoice: 2,
  recommendedTime: 40,
  explanation: "...",
  tags: ["順列", "P", "役割"]
}
```

## 11. 分野

言語: 語彙 / 二語関係 / 熟語 / 語句の意味 / 文の並べ替え / 長文読解

非言語: 割合 / 損益 / 速度 / 仕事算 / 順列 / 組合せ / 確率 / 推論 / 集合 / 表の読み取り / 資料読み取り

将来追加可能な構造にする。

## 12. 学習履歴

問題を回答するたびに履歴を保存する。

```ts
{ questionId: "nonverbal-permutation-001", timestamp: "2026-09-17T23:00:00+09:00", selectedChoice: 1, result: "incorrect", answerTimeMs: 42000 }
```

「わからない」の場合: `{ questionId: "probability-001", result: "unknown", answerTimeMs: 18000 }`

## 13. すべての問題ごとの履歴

各問題ID単位でも学習状況を記録する。最低限: attemptCount / correctCount / incorrectCount / unknownCount / correctRate / averageAnswerTime / lastAnsweredAt / consecutiveCorrect / masteryScore

## 14. 分野ごとの履歴

topic単位でも集計する（回答数、正解、不正解、わからない、正答率、平均解答時間、目安平均）。

## 15. 得意・不得意判定

正答率だけで判定しない。正答率 / 「わからない」率 / 解答時間 / 推奨時間 / 最近の成績 / 回答回数 を考慮する。

## 16. 問題単位のMastery Score

0〜100。初期値 50。正解＋目安時間以内 +8、正解＋目安時間の1〜1.5倍 +5、正解＋1.5倍以上 +2、不正解 −7、わからない −10。0未満・100超にはしない。

## 17. 得意不得意分類

得意: masteryScore >= 75 かつ最低3回答以上。普通: 45〜74。苦手: < 45。未評価: 回答数3未満。サンプル数が少ない段階で断定しない。

## 18. 時間による評価

timeRatio = answerTime / recommendedTime。<= 1.0 速い/適正、1.0〜1.5 やや時間がかかっている、> 1.5 時間面でも要復習。

## 19. 採点後フィードバック

例: 「正解！ 解答時間：24秒 目安時間：30秒 この分野は現在「得意」です。」
例: 「正解 解答時間：72秒 目安時間：30秒 正解していますが、目安時間の2倍以上かかっています。理解はできていますが、処理速度に改善余地があります。」
例: 「わからない この問題は「解法未習得」として記録しました。今後、この分野を優先的に出題します。」

## 20. 出題アルゴリズム

完全ランダムにしない。苦手分野を優先。目安: 40% 苦手 / 30% 通常 / 20% 未評価・新規 / 10% 得意の復習。厳密な比率固定でなくてよい。

## 21. 同じ問題の出題

同じ問題は最低3日程度空ける。ただし「わからない」「連続不正解」の場合は翌日〜数日以内に再出題してよい。

## 22. 苦手分野の優先度

1. 「わからない」が多い 2. 不正解が多い 3. 正解しているが時間が遅い 4. 未評価 5. 得意

## 23. 今日の学習

ホーム画面に「今日のSPIを始める」。初期設定 7問。設定画面で 5/7/10/15 問に変更可能。

## 24. 1日の出題構成

言語と非言語を偏らせない。7問なら 3:4 または 4:3。毎日多少変える。

## 25. 学習終了画面

今日の結果（正解/不正解/わからない、平均解答時間）、得意 / 要復習 / 未評価 の分野一覧。

## 26. 学習履歴画面

全体: 総回答数 / 総正解数 / 正答率 / わからない率 / 平均解答時間 / 学習日数。分野別: 表またはカード（分野 / 回答数 / 正答率 / わからない率 / 平均時間 / 評価）。

## 27. 問題ごとの詳細

問題 / 回答回数 / 過去の回答 / 正答率 / わからない回数 / 平均時間 / masteryScore。

## 28. データエクスポート

「学習データを書き出す」。JSON形式でダウンロード。

## 29. データインポート

エクスポートしたJSONを読み込み、別PC・別ブラウザに学習履歴を復元できる。

## 30. データリセット

設定画面に「学習履歴をすべて削除」。確認ダイアログを出す。

## 31. UI

シンプルで学習に集中できるUI。PC・スマートフォン両対応。レスポンシブ必須。問題画面では余計な情報を表示しすぎない。

## 32-33. 画面イメージ

問題画面: 「問題 3 / 7」「【場合の数】」問題文「[ 問題をはじめる ]」。開始後: 「経過時間 00:23」選択肢4つ「[ わからない ]」「[ 解答する ]」。

解説画面: 正誤、あなたの回答、解答時間、目安、現在の評価（例: 順列：普通 → 得意に近づいています）、解説、POINT、「[ 次の問題 ]」。

## 34. タイマー仕様

ブラウザの再描画回数などに依存しない。開始日時のtimestampを保存し、現在時刻との差から表示する。バックグラウンドでも正しく測れること。

## 35. ページ再読み込み

解答中にリロードしても、可能なら現在の問題・開始時刻を復元する。不可能ならその問題を最初からやり直す。不自然に時間がリセットされないことを優先。

## 36. 問題の追加

questions/ 配下のデータを追加するだけで問題が増える構造にする。分野別ファイルでもよい。

## 37. 問題ID

一意であること。公開後は原則変更しない。

## 38. 問題データのバリデーション

ID重複なし / 選択肢4つ / 正解存在 / 解説存在 / recommendedTimeあり / categoryあり / topicあり を起動時またはbuild時に確認できると望ましい。

## 39. 公開利用

初期版ではアカウントを作らない。履歴は各ユーザーのブラウザに保存される。READMEおよびアプリ内に「学習履歴はこのブラウザに保存されます」と表示する。

## 40. プライバシー

サーバーに学習データを送信しない。Google Analytics等も使用しない。完全ローカル保存。

## 41. 将来拡張（初期版では実装不要）

Supabase / Firebase / GitHub Login / Google Login / クラウド同期 / ランキング / 模擬試験 / 制限時間モード / AIによる問題生成 / ChatGPTによる詳細解説 / 学習曲線グラフ / PWA / オフライン利用

## 42. MVP 必須

GitHub Pagesで動作 / 7問出題 / 問題開始ボタン / タイマー / A〜D / わからない / 個別採点 / 詳細解説 / recommendedTimeとの比較 / 履歴保存 / 問題別履歴 / 分野別履歴 / 得意不得意判定 / 苦手優先出題 / 今日の結果 / 学習履歴画面 / JSONエクスポート / JSONインポート / スマートフォン対応

## 43. 開発優先順位

Phase 1: 問題表示 / 回答 / 個別採点 / タイマー / 解説
Phase 2: IndexedDB / 学習履歴 / Mastery Score
Phase 3: 苦手優先出題
Phase 4: ダッシュボード
Phase 5: export / import
Phase 6: GitHub Pages公開・UI仕上げ

## 44. 初期問題

最低30〜50問程度。可能なら各主要分野5問以上。低品質な問題を量産しない。問題の正確性を最優先。

## 45. 特に重要な設計思想

区別すべき4状態: 1. 速く正解できた 2. 正解したが非常に遅かった 3. 不正解だった 4. わからなかった。「わからない」と「間違えた」を同一扱いしない。

## 46. ユーザーの既存学習傾向（参考・ハードコードしない）

損益・割合: 比較的得意 / 二語関係: 比較的得意 / 順序推論: 比較的得意 / 仕事算: 一度間違えたがその後改善 / 順列・組合せ: PとCの判断に不安 / 確率: 解法が未定着

## 47. 完成条件

1. GitHub Pages URLを開ける 2. 今日の問題を開始できる 3. 問題ごとにタイマーが動く 4. A〜Dまたは「わからない」を選べる 5. 1問ごとに採点される 6. 詳細な解説が表示される 7. 解答時間が保存される 8. 問題別履歴が残る 9. 分野別履歴が残る 10. 得意不得意が変化する 11. 苦手分野の出題率が高くなる 12. ページを閉じても履歴が消えない 13. export/importできる 14. PC・スマホ両方で使える 15. GitHub Pages上で正常動作する

## 48. 実装方針

過度な複雑化を避ける / 将来拡張可能なデータ構造 / TypeScriptの型を明確に / 問題データとアプリロジックを分離 / 学習データの破壊的変更を避ける / UIはシンプルでレスポンシブ / GitHub Pagesでそのまま動作することを確認。実装完了後はREADMEを整備し、GitHub Pagesへのデプロイ方法まで設定する。
